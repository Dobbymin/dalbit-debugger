## 1. 문제 인식: 한국어 프로그래밍 학습의 벽

### 1.1 관찰된 문제점

달빛약속(한국어 프로그래밍 언어)은 프로그래밍 입문자가 한국어로 코딩을 배울 수 있다는 장점이 있지만, 학습 과정에서 치명적인 제약이 있었습니다.

**문제 1: 실행 흐름의 불투명성**
초급 학습자들이 작성한 코드를 실행할 때, 코드가 "어떻게" 움직이는지 보이지 않습니다. 특히 반복문, 조건문 같은 제어 구조는 단순히 "결과만" 나올 뿐, 각 단계에서 무엇이 일어났는지 알 수 없습니다.

```
문제: 1부터 100까지의 합을 구하는 코드가 틀렸을 때
→ 학생은 결과가 잘못됐다는 것만 안다
→ 어느 단계에서 실수했는지 모른다
→ 손으로 직접 계산하거나, 교사의 도움을 기다려야 한다
```

**문제 2: 변수 상태 추적의 어려움**
메모리 상태를 직관적으로 볼 방법이 없습니다. 복잡한 코드에서 어떤 변수가 어떤 값을 가지고 있는지 추적하려면 손으로 매 단계를 기록해야 합니다.

**문제 3: 교육 효율성 저하**
강사 입장에서도, 수업 중 코드를 실행했을 때 학생들에게 동작 원리를 "보여주기"가 어렵습니다. 기존의 통합 개발 환경(IDE)은 너무 복잡하고, 달빛약속만을 위한 간단한 학습 도구가 없었습니다.

### 1.2 대상 사용자의 고충

- **초급 대학 학생**: "내 코드가 왜 틀렸을까?"를 체계적으로 파악할 수 없음
- **코딩 방과후 강사**: 수업 중 실시간으로 개념을 보여줄 도구가 없음
- **자학 개발자**: 복잡한 로직을 디버깅할 전문 도구가 없음

## 2. 아이디어 탐색: 여러 선택지 검토

프로젝트 시작 시, 달빛약속의 기능을 활용하여 어떤 웹 애플리케이션을 만들 것인가를 고민했습니다.

### 2.1 검토한 선택지들

#### 선택지 1: 플레이그라운드 (Playground)
**개념**: 달빛약속 코드를 작성하고 즉시 실행 결과를 보는 간단한 환경

**장점**:
- 구현이 빠르고 단순함
- "실행하면 결과가 나온다"는 기본 기능만 제공

**단점**:
- 학습자가 버그를 찾는 데 도움이 되지 않음
- 코드의 동작 원리를 이해하는 데 기여하지 못함
- 교육적 효과가 제한적

**판단**: 이 프로젝트에서는 너무 수동적. 초보자가 필요한 "왜?"를 답변할 수 없음.

---

#### 선택지 2: 인터랙티브 튜토리얼
**개념**: 달빛약속 문법을 단계별로 배우는 가이드, 각 단계마다 맞춤형 코드 예제 제공

**장점**:
- 구조화된 학습 경로
- 강의식 교육 가능

**단점**:
- 콘텐츠 제작 비용이 큼 (튜토리얼 시나리오, 이미지, 비디오 등)
- 문법이 업데이트될 때마다 전체 수정 필요
- 사용자의 자유도가 낮음 (정해진 경로만 따라야 함)
- 4일이라는 제한된 일정 내에 적절한 깊이의 콘텐츠 생성 어려움

**판단**: 충분한 콘텐츠 없이는 실제 학습 효과를 기대하기 어려움. 범위가 너무 큼.

---

#### 선택지 3: 흐름도/순서도 변환 도구
**개념**: 달빛약속 코드를 흐름도(flowchart)나 순서도(sequence diagram)로 자동 변환

**장점**:
- 시각적으로 흥미로움
- 알고리즘 이해에 도움

**단점**:
- AST 분석과 흐름도 생성 알고리즘 구현이 매우 복잡
- 복잡한 코드의 흐름도는 오히려 이해를 방해할 수 있음
- 실제 실행 데이터 (변수 값, 출력)가 반영되지 않으므로 디버깅에 도움 안 됨
- 4일 일정 내 완성도 있는 결과물 만들기 어려움

**판단**: 기술적 복잡도는 높지만, 실제 학습 효과는 불명확함.

---

#### 선택지 4: 스텝 디버거 (Step-by-Step Debugger) ✓
**개념**: 코드를 한 줄씩 실행하면서 각 단계의 변수 상태, 실행 흐름, 출력을 실시간으로 보여주는 도구

**장점**:

1. **직접적인 교육 효과**
   - "코드가 어떻게 동작하는가"를 눈으로 직접 볼 수 있음
   - 초보자가 "왜"를 이해할 수 있음

2. **달빛약속 API 활용도**
   - `YaksokSession`의 `runningCode` 이벤트를 활용하면 각 실행 단위를 캡처할 수 있음
   - `pause()`, `resume()` API로 단계별 제어 가능
   - 런타임에서 변수 상태(scope)를 직접 받을 수 있음
   - 이미 제공되는 API를 충실히 활용하는 것

3. **다양한 사용 시나리오 지원**
   - 초급 학생의 숙제 디버깅
   - 강사의 수업 중 실시간 설명
   - 자학 개발자의 복잡한 로직 추적

4. **차별성**
   - 기존 Python, Java 디버거와는 다르게 "한국어 코드"를 대상으로 함
   - 달빛약속 생태계에서 유일한 전문 학습 디버거
   - 웹 기반이므로 설치 불필요

5. **적절한 기술 복잡도**
   - 달빛약속의 기본 API만 사용해도 구현 가능
   - React + Vite로 빠른 개발 가능
   - 4일 일정 내에 MVP 완성 현실적

**단점**:
- UI/UX 설계가 신경 써야 할 부분이 많음
- 많은 양의 정보(줄, 변수, 출력)를 동시에 표시해야 함

**판단**: **이것이 우리가 해야 할 일이다.** 문제를 가장 직접적으로 풀면서도, 달빛약속 API를 충실히 활용하고, 한정된 일정 내에 완성 가능한 최적의 선택.

## 3. 방향 결정: 왜 스텝 디버거인가?

### 3.1 핵심 가치 명제

**"코드가 어떻게 동작하는가를 눈으로 보여준다"**

이것이 스텝 디버거의 핵심 가치입니다.

초급 학습자가 막히는 순간은 대부분 "결과가 틀렸다"는 것을 발견한 후입니다. 이 순간:
- 어디서 실수했는가?
- 어느 변수가 예상과 다른가?
- 어느 줄에서 분기가 잘못됐는가?

이런 질문들에 "단계별 실행"을 통해 명확한 답을 줄 수 있습니다.

### 3.2 교육적 임팩트

**초급 학생의 관점**:
```
전: "코드를 실행했는데 틀렸다" → 무기력함
후: "3번 줄에서 변수 값이 잘못됐네" → 직접 수정 가능
```

**강사의 관점**:
```
전: 수업 중 "이 부분이 실행됩니다" (말로만 설명)
후: 빔프로젝터에 실시간 변수 값 표시 → 학생이 직관적으로 이해
```

### 3.3 기술적 적절성

달빛약속 런타임(`@dalbit-yaksok/core`)은 이미 다음을 제공합니다:

```typescript
events: {
  runningCode(start, end, scope, tokens) {
    // 각 실행 단위마다 호출됨
    // start/end: 현재 줄과 열 정보
    // scope: 현재 메모리 상태
    // tokens: 현재 단위의 토큰
  }
}
```

이 이벤트를 활용하면, 별도의 복잡한 파싱이나 AST 변환 없이도 런타임이 직접 제공하는 정보로 디버거를 구축할 수 있습니다.

## 4. 설계 구체화 과정

### 4.1 단계 1: PRD 작성 (2026-04-23)

초기 아이디어를 정리하면서, 다음을 명확히 했습니다:

**문제 정의 구체화**:
- "코드 실행 흐름의 추상성" → "현재 실행 중인 줄을 에디터에서 강조"로 해결
- "변수 상태의 불가시성" → "현재 스코프의 모든 변수를 패널에 표시"로 해결
- "한국어 언어의 학습 진입 장벽" → "웹 기반, 설치 불필요"로 해결

**타겟 페르소나 정의**:
- 페르소나 1: 초급 대학 학생 (김영준, 21세)
- 페르소나 2: 방과후 교실 강사 (박지은, 35세)
- 페르소나 3: 자학 개발자 (이준호, 28세)

각 페르소나의 사용 시나리오를 상세히 작성함으로써, 기능 우선순위를 명확히 했습니다.

**기능 우선순위 결정**:
- P0 (필수): 코드 에디터, 단계별 실행, 변수 표시, 출력 로그
- P1 (높음): 자동 실행, 속도 조절, 전체 실행
- P2 (중요): 에러 처리, 반응형 레이아웃
- P3 (추가): 예제 라이브러리

### 4.2 단계 2: 아키텍처 결정

**왜 Feature-Sliced Design (FSD)?**

초기에는 "꼭 FSD가 필요한가?"라는 질문도 있었습니다. 하지만:

1. **계획적 확장성**:
   - 예제 추가, 새로운 시각화 기능 추가 등이 쉬워야 함
   - FSD로 각 기능을 독립적인 슬라이스로 관리 가능

2. **명확한 책임 분리**:
   - `entities`: debug-session, code-editor (비즈니스 엔티티)
   - `features`: debugger, examples (복합 기능)
   - `pages`: 최상위 페이지 컴포넌트
   - 각 레이어가 명확히 분리되어, 팀 협업 시 병렬 작업 가능

3. **에이전트 협업의 용이성**:
   - 단일 파일이 너무 많은 책임을 지지 않음
   - 각 기능별로 독립적으로 지시 가능
   - 에이전트가 아키텍처 규칙을 어기기 어렵게 구조화

결론: **FSD는 선택이 아니라 필수**

### 4.3 단계 3: 기능 세분화

**핵심 실행 모드 정의**:

| 모드 | 목적 | 사용자 |
|------|------|--------|
| 단계 모드 | 버튼 클릭마다 한 줄 | 초급 학생, 디버깅 |
| 자동 실행 | 설정 속도로 연속 실행 | 강사, 자학 개발자 |
| 전체 실행 | 즉시 완료, 결과만 | 빠른 검증 |

각 모드가 다른 사용 사례를 지원하므로, 세 가지 모두 필수입니다.

**데이터 구조 설계**:

```typescript
type StepFrame = {
  stepIndex: number           // 몇 번째 단계인가
  line: number                // 몇 줄을 실행했는가
  columnStart/columnEnd: number // 정확한 범위
  scope: ScopeVariable[]      // 이 단계의 변수 상태
  output: string[]            // 이 단계까지의 출력
}

type DebugState = {
  mode: RunMode               // 현재 상태
  frames: StepFrame[]         // 모든 단계의 기록
  currentFrameIndex: number   // 현재 보는 단계
  // ...
}
```

이 구조는 "모든 단계를 기록하되, 사용자가 보는 것은 하나의 단계"라는 원칙을 구현합니다.

### 4.4 단계 4: MVP 범위 확정

**MVP (Minimum Viable Product)에 포함**:
- ✅ 코드 에디터 (Monaco + 달빛약속 언어 공급자)

**MVP에서 제외**:

- ❌ 브레이크포인트
- ❌ 클라우드 저장
- ❌ 협업 기능

## 5. 설계 구체화의 주요 결정사항

### 5.1 왜 Monaco Editor인가?

**선택 사항**:
- Ace Editor: 가볍지만, 확장성 제한
- CodeMirror: 경량, 하지만 달빛약속 지원 미흡
- Monaco Editor: VS Code의 에디터, 강력한 언어 통합, 달빛약속 공식 지원

**결정**: Monaco Editor + `@dalbit-yaksok/monaco-language-provider`
- 달빛약속이 공식 지원하는 통합이 있음
- 한국어 문법 하이라이팅이 정확함
- 현재 줄 강조, 줄 번호 등 모든 기능 기본 제공

### 5.2 왜 PandaCSS인가?

**선택 사항**:
- Tailwind CSS: 가장 인기, 하지만 런타임 클래스 생성 주의 필요
- Styled Components: JS-in-CSS, 동적 스타일에 강함
- PandaCSS: 타입 안전 CSS-in-JS, 정적 추출 가능

**결정**: PandaCSS
- TypeScript 타입 안전성 (프로젝트의 strict 모드와 맞음)
- 런타임 오버헤드 최소화
- 다양한 ui 상태를 type-safe하게 표현 가능

### 5.3 상태 관리: 왜 단순 reducer인가?

**선택 사항**:
- Redux: 과도함 (4일 프로젝트에는 너무 무거움)
- Zustand: 가볍고 좋지만, FSD에서 `_stores` 구조와 맞지 않을 수 있음
- Context API: React 기본, 하지만 대규모 상태엔 성능 이슈

**결정**: Reducer (useReducer 또는 custom hook)
- 상태 변화가 명확함 (누가 언제 어떤 상태를 바꿨는지 추적 가능)
- FSD의 `entities/{name}/model/stores` 구조와 자연스럽게 맞음
- 에이전트와의 협업 시 상태 흐름을 명확히 설명 가능

## 6. 핵심 통찰

이 프로젝트를 진행하면서 얻은 핵심 통찰은 다음과 같습니다.

### 6.1 "시각화"가 교육의 핵심이다

프로그래밍 초보자가 막히는 이유는 대부분 **추상적 개념**이 아니라 **구체적 데이터**입니다.

```
틀린 이해: "초보자가 반복문 개념을 몰라서 헤맨다"
옳은 이해: "초보자가 이 반복에서 변수 값이 어떻게 변하는지 몰라서 헤맨다"
```

반복문의 개념을 100번 설명하는 것보다, "이 단계에서 `i` 값이 0에서 1로 변했다"는 것을 눈으로 보여주는 것이 1000배 효과적입니다.

따라서 디버거는 단순한 "도구"가 아니라 **교육 매체**입니다.

### 6.2 "한국어 코딩"의 장점을 살려야 한다

달빛약속은 "한국어"라는 특성이 있습니다. 이는:
- **배리어 낮음**: 영어를 모르는 초등학생도 시작 가능
- **교육 자원 풍부**: 한국의 많은 학교와 학원이 사용
- **지역적 우위**: 영어권과 달리, 한국에서 "유일한" 한국어 프로그래밍 환경

따라서 이 디버거가 성공하려면, **달빛약속 생태계 내에서 필수 도구**가 되어야 합니다.

### 6.3 "실행 중인 줄" + "변수 값" + "출력"의 조합이 강력하다

세 가지가 모두 있어야 합니다:
1. **실행 중인 줄**: "지금 여기를 실행 중"
2. **변수 값**: "지금 메모리가 이 상태"
3. **출력**: "지금까지 나온 결과"

이 세 가지가 동시에 업데이트될 때, 초보자도 "아, 이 코드가 이렇게 동작하는구나"를 직관적으로 깨닫습니다.

### 6.4 "단계별 모드"와 "자동 실행 모드"는 다른 사용자를 위한 것이다

초기에는 "단계별 모드만 있으면 되지 않을까?"라는 생각도 있었습니다. 하지만:

- **단계별 모드**: 초급 학생이 "내 코드가 왜 틀렸을까?"를 디버깅할 때 필요
- **자동 실행 모드**: 강사가 수업 중 "이 알고리즘이 어떻게 동작하는지 보여주기"에 필요

두 사용 사례가 다르기 때문에, 두 모드 모두 필수입니다.

## 7. 최종 설계 요약

### 7.1 프로젝트의 정의

**"달빛약속 스텝 디버거는 코드를 한 줄씩 실행하면서 각 단계의 변수 상태와 출력을 시각적으로 보여주는 웹 기반 학습 도구입니다."**

### 7.2 해결하는 문제들

| 문제 | 해결 방법 |
|------|----------|
| 코드 실행 흐름의 불투명성 | 현재 줄 강조 + 단계별 진행 |
| 변수 상태 추적 어려움 | 변수 패널에서 매 단계마다 표시 |
| 교육 도구 부족 | 자동 실행 + 속도 조절로 수업 지원 |
| 초보자의 디버깅 무기력함 | 변수 값 추적으로 원인 파악 가능 |

### 7.3 기술 기반

- **언어**: TypeScript (strict mode)
- **프레임워크**: React 19
- **스타일**: PandaCSS
- **에디터**: Monaco Editor + 달빛약속 언어 공급자
- **런타임**: @dalbit-yaksok/core (YaksokSession API)
- **아키텍처**: Feature-Sliced Design

### 7.4 핵심 기능

**P0 (필수)**:
- 달빛약속 코드 에디터 (문법 하이라이팅 포함)
- 단계별 실행 모드
- 자동 실행 모드
- 변수 상태 패널
- 출력 로그 패널

**P1 (높음)**:
- 실행 속도 조절
- 전체 실행 모드
- 기본 에러 처리

**P2 (중요)**:
- 예제 코드 라이브러리
- 반응형 레이아웃
