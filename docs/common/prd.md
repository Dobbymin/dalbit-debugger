## 1. 프로젝트 배경 및 목적

### 1.1 문제 정의

프로그래밍을 배우는 초급 학습자들은 다음과 같은 어려움을 겪습니다:

- **코드 실행 흐름의 추상성**: 작성한 코드가 실제로 어떻게 실행되는지 눈에 보이지 않음
- **변수 상태의 불가시성**: 각 단계에서 변수의 값이 어떻게 변하는지 추적하기 어려움
- **디버깅 기술 부재**: 에러가 발생했을 때 원인을 찾기 위한 체계적인 방법을 모름
- **한국어 프로그래밍 언어의 학습 진입 장벽**: 달빛약속은 한국어 기반 언어이지만, 실행 과정을 시각화할 도구가 부족함

### 1.2 솔루션 비전

**달빛약속 스텝 디버거**는 다음을 제공합니다:

- **단계별 실행 시각화**: 코드를 한 줄씩 실행하면서 각 단계를 명확하게 관찰
- **실시간 변수 상태 추적**: 현재 스코프의 모든 변수를 시각적으로 표시
- **실행 흐름 강조**: 현재 실행 중인 줄을 에디터에서 하이라이트
- **누적 출력 로그**: 프로그램의 모든 출력을 시간 순서대로 표시
- **직관적인 UI**: 코딩 초보자도 쉽게 이해할 수 있는 인터페이스

### 1.3 핵심 목표

1. **교육 효과**: 학습자가 "코드가 어떻게 동작하는가"를 직관적으로 이해하게 한다
2. **낮은 학습 곡선**: 추가 학습 없이 웹 브라우저에서 즉시 시작할 수 있다
3. **달빛약속 생태계 강화**: 한국어 프로그래밍 언어의 학습 환경을 개선한다
4. **프로토타입 검증**: 향후 달빛약속 IDE에 통합할 수 있는 기반을 마련한다

## 2. 타겟 사용자

### 2.1 주요 페르소나

#### 페르소나 1: 대학 프로그래밍 초급 강좌 학생 (21세, 김영준)

- **배경**: 컴퓨터공학 전공 1학년, 프로그래밍이 처음
- **목표**: 프로그래밍 기초를 이해하고 숙제를 완료하고 싶음
- **고충**: 반복문, 조건문이 어렵고, 디버깅하는 방법을 모름
- **기대**: 코드를 천천히 실행해서 변수 값 변화를 눈으로 확인하고 싶음
- **사용 시나리오**: 수업 시간에 배운 개념을 복습할 때, 버그가 생겼을 때

#### 페르소나 2: 코딩 방과후 교실 강사 (35세, 박지은)

- **배경**: 초등학교 고학년을 대상으로 프로그래밍 수업
- **목표**: 학생들에게 프로그래밍 개념을 시각적으로 설명하고 싶음
- **고충**: 기존 디버거 도구는 너무 복잡하고, 한국어 지원이 부족함
- **기대**: 학생이 쉽게 이해할 수 있는 시각화 도구가 필요함
- **사용 시나리오**: 수업 중 실시간으로 코드를 실행해서 설명할 때, 학생의 오류 코드를 함께 분석할 때

#### 페르소나 3: 달빛약속 자학 개발자 (28세, 이준호)

- **배경**: 자유로운 시간에 달빛약속으로 프로젝트를 만들고 싶음
- **목표**: 달빛약속 언어 자체를 더 깊이 이해하고, 효율적으로 개발하고 싶음
- **고충**: 현재 달빛약속의 디버깅 도구가 매우 제한적임
- **기대**: 프로페셔널한 디버거로 복잡한 로직을 체계적으로 추적하고 싶음
- **사용 시나리오**: 자신의 달빛약속 코드를 개발하고 테스트할 때

### 2.2 사용자 특성

- **프로그래밍 수준**: 초급~중급
- **기술 숙련도**: 웹 브라우저 사용 가능한 수준
- **언어**: 한국어 우선
- **접근성**: 웹 기반 (설치 불필요)

## 5. 기술 아키텍처 개요

### 5.1 아키텍처 패턴: Feature-Sliced Design (FSD)

프로젝트는 **Feature-Sliced Design (FSD)** 아키텍처를 따릅니다. 이를 통해 다음을 달성합니다:

- **수평적 확장성**: 새로운 기능 추가가 기존 코드에 영향을 주지 않음
- **단방향 의존성**: 상위 레이어만 하위 레이어를 의존
- **높은 응집도**: 관련 기능이 한 곳에 모여 있음

### 5.2 페이지 구성 (현재 코드 기준)

| `/` | `MainPage.tsx` | 랜딩/진입 페이지 |
| `/debugger` | `DebuggerPage.tsx` | 디버거 메인 화면 |
| `/examples` | `ExamplesPage.tsx` | 예제 페이지 |
| `*` | `NotFound.tsx` | 잘못된 경로 처리 |

### 5.5 상태 관리 (State Management)

```typescript
// src/entities/debug-session/model/types/* (구현 예정)

type RunMode = 'idle' | 'running' | 'paused' | 'finished' | 'error'

type StepFrame = {
  stepIndex: number
  line: number              // 1-based 라인 번호
  columnStart: number       // 열 시작 위치
  columnEnd: number         // 열 끝 위치
  scope: ScopeVariable[]    // 현재 스코프의 모든 변수
  output: string[]          // 이 스텝까지의 누적 출력
}

type DebugState = {
  mode: RunMode             // 현재 실행 상태
  currentLine: number | null
  frames: StepFrame[]       // 모든 실행 단계의 기록
  currentFrameIndex: number // 현재 보고 있는 단계
  output: string[]
  error: string | null
  speed: number             // executionDelay (ms)
}
```

### 5.6 핵심 타입 및 인터페이스

#### ScopeVariable (변수 표현)
```typescript
type ScopeVariable = {
  name: string      // 변수명 ("나이", "점수" 등)
  value: string     // 렌더링용 값 ("20", "[1, 2, 3]" 등)
  type: string      // 타입 ("number", "string", "list" 등)
}
```

#### YaksokSession Events (달빛약속 런타임 이벤트)
```typescript
interface YaksokSessionOptions {
  stdout: (message: string) => void
  events: {
    runningCode: (
      start: { line: number; column: number },
      end: { line: number; column: number },
      scope: Record<string, unknown>,
      tokens: unknown[]
    ) => void
    pause: () => void
    resume: () => void
  }
}
```

### 5.7 통신 흐름

1. **사용자 코드 작성** → editor 관련 상태 업데이트
2. **실행 버튼 클릭** → `features/debugger/_hooks`에서 세션 생성/제어 로직 실행 (구현 예정)
3. **YaksokSession.runModule()** 호출 → 달빛약속 런타임 시작
4. **runningCode 이벤트** → 각 실행 단위마다 발생
5. **store/reducer 로직** → DebugState 업데이트
6. **UI 재렌더링** → 모든 패널 동기화

## 6. 사용자 시나리오 (User Story)

### 시나리오 1: 초급 학생의 첫 디버깅 경험

**페르소나**: 김영준 (대학 프로그래밍 초급 학생)

**목표**: 반복문을 이해하고, 왜 자신의 코드가 원하는 대로 작동하지 않는지 파악하기

**상황**:
- 숙제: "1부터 5까지의 합을 출력하는 프로그램 작성"
- 학생이 작성한 코드: 변수 초기화에 문제가 있어 결과가 틀림

**흐름**:
1. 디버거 웹 페이지에 접속
2. 자신의 코드를 에디터에 붙여넣음
3. "단계별 실행" 모드 선택
4. "다음 단계" 버튼을 반복해서 클릭
5. 각 단계마다:
   - 현재 실행 중인 줄이 에디터에 강조됨
   - 변수 패널에서 `반복값`, `합계` 변수의 값 변화를 관찰
   - 출력 로그에서 각 단계의 결과 확인
6. 변수 값이 예상과 다른 지점을 발견
7. 코드를 수정하고 다시 실행
8. 올바른 결과 확인 (각 단계의 변수 값이 기대값과 일치)

**기대하는 UX**:
- 버튼을 누를 때마다 정확히 한 줄씩만 실행
- 변수 값이 실시간으로 업데이트
- 색상 강조로 현재 위치를 명확하게 인지

### 시나리오 2: 강사의 수업 설명

**페르소나**: 박지은 (코딩 방과후 교실 강사)

**목표**: 학생들에게 조건문의 동작 방식을 실시간으로 보여주기

**상황**:
- 수업 내용: "나이를 입력받아 성인 여부를 판정하기"
- 학생들이 이 개념을 어려워함

**흐름**:
1. 강의실의 빔프로젝터에 디버거를 띄움
2. 예제 코드를 에디터에 로드 (또는 예제 라이브러리에서 "조건문" 예제 선택)
3. 학생들이 보는 앞에서 "자동 실행" 모드를 선택하고 속도를 느리게 설정
4. 실행 버튼 클릭
5. 코드가 천천히 실행되면서:
   - 변수 `나이`가 입력됨
   - 조건문이 평가됨 (변수 값 확인)
   - 적절한 분기가 실행됨
6. 속도를 조절하면서 설명:
   - "보세요, `나이` 변수가 18이 되었습니다"
   - "이제 조건을 확인합니다: 18 >= 18은 참이므로..."
   - "따라서 이 부분이 실행됩니다"
7. 학생에게 다른 나이값으로 다시 시뮬레이션할 수 있음을 보여줌

**기대하는 UX**:
- 속도 슬라이더로 쉽게 속도 조절
- 변수 값과 실행 흐름이 동시에 강조
- 빔프로젝터에서도 충분히 크게 표시되는 글자 크기

### 시나리오 3: 자학 개발자의 복잡한 로직 디버깅

**흐름**:
1. 디버거에 코드 붙여넣음
2. 처음에는 자동 실행으로 전체 흐름을 빠르게 확인
3. 의심 부분에 도달했을 때 일시정지 버튼 클릭
4. 단계별 실행 모드로 전환

   - 내부 반복문의 인덱스
   - 임시 변수들

7. 버그 원인 발견: "아, 내부 반복문이 한 번 더 반복되고 있네"
8. 코드 수정 후 다시 테스트

**기대하는 UX**:
- 복잡한 변수 상태를 한 눈에 볼 수 있는 레이아웃
- 실행 중 언제든지 일시정지/단계 실행 모드 전환 가능
- 실행 히스토리를 추적할 수 있음 (이전 단계의 변수 값 재확인)

- ✅ 기본 에러 핸들링 및 에러 메시지 표시
- ✅ 반응형 레이아웃 (데스크톱 최적화)
- ✅ Monaco Editor 기반의 코드 에디터
- ✅ PandaCSS 스타일링
- ✅ TypeScript strict 모드 준수

### 7.2 하지 않을 것 (Out of Scope)

- ❌ 달빛약속 IDE와의 완전한 통합 (버전 1.0에서는 독립형 웹 앱)
- ❌ 클라우드 저장 및 파일 관리 (로컬 세션만)
- ❌ 협업 기능 (한 명의 사용자가 사용하는 것을 기준)
- ❌ 실행 취소(Undo) / 재실행(Redo) 기능 (코드 에디터에서만 가능)
- ❌ 이전 단계로 되감기 (항상 순방향)
- ❌ 브레이크포인트 설정 (버전 1.0에서는 미지원)
- ❌ 성능 프로파일링 (실행 시간 측정 등)
- ❌ 모바일 앱 (웹만 지원)
- ❌ 오프라인 모드 (온라인 필수)
- ❌ 달빛약속 컴파일러 수정 (patch만 사용)

### 7.3 기술적 제약

| 제약 | 설명 |
|-----|------|

## 9. 성공 지표 (Definition of Done)

### 9.1 기능적 성공 기준

| 기능 | 성공 기준 | 검증 방법 |
|-----|---------|---------|
| **코드 에디터** | 달빛약속 코드를 입력할 수 있고, 문법 하이라이팅이 작동함 | 수동 테스트 |
| **단계별 실행** | 버튼 클릭마다 정확히 한 단위만 실행되고, 모든 단계의 변수가 올바르게 표시됨 | 단계별 실행 테스트 (최소 5개 예제) |
| **자동 실행** | 설정 속도로 연속 실행되고, 속도 조절이 정상 작동함 | 속도 테스트 (100ms, 500ms, 2000ms) |
| **변수 표시** | 모든 변수가 정확하게 표시되고, 단계마다 업데이트됨 | 100개 이상의 변수가 있는 코드로 테스트 |
| **출력 로그** | 모든 출력이 누적으로 표시되고, 순서가 정확함 | 반복문/함수 예제로 테스트 |
| **에러 처리** | 에러 발생 시 명확한 메시지 표시, UI가 깨지지 않음 | 잘못된 코드로 테스트 |

```
합계 : 0

합계 보여주기
```

### 10.3 용어 정의

| 용어 | 정의 |
|-----|------|
| **스텝(Step)** | 코드의 최소 실행 단위 (한 줄 또는 표현식) |
| **스코프** | 현재 메모리에 존재하는 변수들의 영역 |
| **프레임** | 한 스텝의 정보 (줄, 변수, 출력)를 담는 데이터 구조 |
| **단계별 실행(Step-by-Step)** | 사용자 입력에 따라 한 번에 한 스텝만 실행 |
| **자동 실행(Auto Run)** | 설정된 속도로 자동으로 연속 실행 |
| **런타임 에러** | 코드 실행 중 발생하는 에러 |
